## 背景

传统 Web 产品文档需要人工登录系统、遍历菜单、验证操作、逐步截图、添加标注并编写说明。页面发生变化后，截图、编号和文字还要重新核对，重复工作多，也容易出现文案与真实界面不一致。

该项目让 AI Agent 基于真实 Web 界面生成产品文档。用户只需要提供产品入口和需要记录的流程，AI 就能操作浏览器完成登录、菜单遍历、页面探索、截图标注和操作说明编写。产品页面或流程变化后，可以重新执行对应任务，更新截图和文档，不需要人工重新走完整套截图与整理流程。

## 我负责的部分

设计 AI Agent 浏览器自动化能力，让 AI 根据用户目标和真实页面状态选择需要执行的动作。AI 负责判断是否登录、需要探索哪些菜单、如何拆分页面、哪些弹窗可以关闭以及哪些内容需要脱敏；稳定且可重复的动作交给 JavaScript 工具完成。

开发支持自定义颜色和布局的截图标注工具。AI 传入需要说明的控件和标注文案，工具读取控件边界，在页面中动态注入 SVG 方框、编号、箭头和说明文字，同时生成无标注图与标注图；截图结束后自动移除 SVG 图层并恢复临时脱敏内容。

设计 local 与 CDP 两种浏览器会话模式。local 模式启动独立 Chromium 和临时 Profile；CDP 模式通过 Playwright 的 `connectOverCDP()` 接入外部 Chromium，复用客户已有页面和登录状态。会话层会按域名与路径选择目标页面，并区分外部资源和任务自建资源，结束时只清理本任务拥有的 Page、连接和 Profile。

菜单探索以真实页面为依据，生成结构化 JSON 作为唯一数据源；页面探索记录入口、用途、交互结果、滚动模型和截图计划。对提交、删除、上传等有副作用的操作单独要求授权，不根据源码或控件名称臆测业务结果。

截图流程会先判断弹窗是否属于当前业务步骤，再对允许进入文档的普通数据临时脱敏，读取目标控件边界并注入 SVG 方框、编号、箭头和说明文字，同时生成无标注图与标注图。无论成功或失败，都会恢复脱敏内容并清理临时覆盖层；密码、令牌、Cookie、私钥等安全凭据禁止进入截图和项目文件。

最后将菜单数据、页面事实、操作步骤和标注截图整理为用户手册章节。项目同时沉淀 8 份行为规则和 5 个 JavaScript 工具，累计通过 31 项回归测试。

## 结果

跑通从真实页面操作、截图标注、操作说明编写到用户手册生成的完整流程，将原本需要人工逐页操作、截图、标注和整理文字的工作交给 AI 执行。

该能力已用于真实管理平台的功能盘点和用户手册建设。后续产品页面或操作流程变化时，只需让 AI 重新执行对应页面或流程，即可更新页面事实、截图和文档章节，减少重复人工维护。
